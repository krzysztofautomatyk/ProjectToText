# Desktop installers

The installers are generated by Tauri from the configuration committed in
the repository. Native installer binaries are intentionally not committed to
Git; they are reproducible build artifacts under `target/release/bundle/` and
are attached to GitHub Releases by `.github/workflows/release.yml`.

## macOS

Run on macOS from the repository root:

```bash
./installer/build-macos.sh
```

This creates an ad-hoc signed `.app` and `.dmg`. The app is not notarized. To build a specific architecture:

```bash
./installer/build-macos.sh --target aarch64-apple-darwin
./installer/build-macos.sh --target x86_64-apple-darwin
```

The corresponding architectures require the Rust targets to be installed.
The release workflow builds both architectures separately. A target-specific
build is written under `target/<target>/release/bundle/`.

## Windows

Run in PowerShell on Windows from the repository root:

```powershell
powershell -ExecutionPolicy Bypass -File .\installer\build-windows.ps1
```

This creates both an `.msi` installer (WiX) and an `.exe` installer (NSIS).
The installer embeds the WebView2 bootstrapper and installs per user by
default, so administrator privileges are not required for a normal install.

## Signing

Local builds and the default GitHub workflow are unsigned. For public
distribution, configure Apple Developer signing/notarization and Windows
Authenticode signing in CI; the bundle configuration is ready to accept those
credentials without committing secrets.
